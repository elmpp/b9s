## Highlights

### A redesigned web UI with a style of its own

Until now, `b9s web` was the terminal UI in a browser: the same palette, the same density and the same layout, squeezed onto a smaller or a bigger screen. This release departs from that on purpose. Reading your issues on a phone in your hand, on a tablet on the sofa or in a desktop browser is a different way of using the same data than working in a terminal, and it deserves its own look, its own flow and its own way of working.

The new web UI is calm and minimal. Colour appears only as small state marks, prose is set in a readable web font, and the chrome steps back so the issues get the space. The layout fits the device it runs on (ADR 0052), so one URL works on a phone, a tablet and a desktop browser, and each one feels at home there:

- **Phone.** A bottom bar holds Tree, Board, Memory, Search and More. Tap an issue to open it in a sheet: it starts at half height, `⌃` makes it full height, and `‹ Tree` or `✕` closes it. Rows and buttons are at least 44 px high. The board stacks its columns as boxes, one below the other: tap a box header to fold it, and the fold survives a reload.
- **Tablet.** The list stays at the left and the detail fills the rest of the screen, upright and on its side. A rotation keeps your place in the detail.
- **Desktop** (from 1280 px). A sidebar holds the project, the views and the connection. The detail is a third column beside the tree or the board. Rows light up under the pointer, and a right click (or `Menu`, or `Shift+F10`) on a row, a card or an epic cell opens a context menu.

The data, the filters and the writes through `bd` stay the same as in the terminal. With a keyboard, the same keys work in every layout: `j`/`k` move, `d` opens the detail, `n`/`p` step through issues, `b` opens the board and `Esc` closes.

### Epic rail lanes in three heights

On the web board from 768 px wide, every epic lane starts **Compact**: the height of its epic cell and at least three one-line cards. `Tab`, or the arrow in the epic cell, steps the lane to **Open**, which shows every open and in-progress card, and then to **Full**, the height of its tallest cell. `Shift+Tab` steps every lane together. One busy epic no longer pushes the others off the screen (ADR 0053). Only the cell that holds the cursor scrolls, and the cursor keys keep the selected card in view (ADR 0054). `PageUp` and `PageDown` page in every view.

### Comment when you close an issue

The close dialog for a single issue offers `[C] Comment`. `Enter` adds the comment with `bd comments add` and then closes the issue. If the comment fails, the issue stays open.

### Mark issues as dired does

In the tree, `m` marks the issue at the cursor and moves down, so repeated presses mark consecutive issues. `u` unmarks and moves down, `Backspace` moves up and unmarks, and `U` clears every mark.

### Gas City and other proxied-server stores

b9s opens a Beads store that `bd` serves through a loopback proxy in front of a private Dolt server, as Gas City does. It finds the proxy port the same way `bd` does and never sends `BEADS_DOLT_PASSWORD` to such a store.

### The version names its commit

`b9s --version`, the `?` help overlay and the web app's More tab show the version and the commit it was built from, linked to GitHub. A build from `go install` or a local checkout reads as `dev after <tag>`.

### Live preview for web development

`make web-dev` rebuilds the web UI on every change, and `b9s web --dev-assets <dir>` serves it from that folder. Every open browser reloads on the same view and issue.

## Fixes

- The edit form saves with `Enter` from single-line fields and selects, and a line under the title names the save and cancel keys. Description and Notes keep `Enter` for line breaks. (#21)
- A live reload keeps the tree's folds and the selected issue in the detail. Under a status filter, the tree no longer popped open and the detail no longer switched to another issue.
- The header legend names `C` for the closed filter.
- In `b9s web`, `Enter` right after `Esc` opens the detail again, and a reload keeps the open issue.
- On a phone, the top bar and the bottom bar stay on screen after a pinch zoom.

## Upgrade notes

- In the tree, `U` clears every mark. The command that asks before it updates b9s moves from `U` to `:update`.

## Documentation

- The README is a front page: what b9s does, how to install it and where to read on. The User Guide is the reference for every view and key.
- The web guide describes the phone, tablet and desktop layouts.
- ADR 0052 records the responsive web direction, ADR 0053 the epic rail lane heights and ADR 0054 the scrolling of the cursor's cell.
